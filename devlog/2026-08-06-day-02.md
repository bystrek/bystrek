# Day Two — bystrek.dev

**Date:** 2026-08-06
**Goal:** Get a real chat UI talking to Claude, replacing the placeholder landing page's underlying stack with a working assistant.

## What we did

1. **Deployed Open WebUI**: replaced the `web` (nginx placeholder) service in `~/bystrek/docker-compose.yml` with `ghcr.io/open-webui/open-webui:main`, backed by a persistent named volume (`open_webui_data:/app/backend/data`) for its SQLite DB, chat history, and connection config. No published host port — same pattern as before, reachable only through Caddy's reverse proxy over Tailscale.
2. **Updated the Caddyfile**: `reverse_proxy` target changed from `web:80` to `open-webui:8080`.
3. **Connected Claude**: in Open WebUI's Admin Settings → Connections, added an **OpenAI**-type connection (not Ollama) using the **Chat Completions** API type (not Responses — Anthropic's OpenAI-compatibility layer only implements `/v1/chat/completions`, not OpenAI's newer Responses API). Base URL `https://api.anthropic.com/v1`, key from the local `CLAUDE_API_KEY` in `~/Documents/bystrek.dev/.env`. Manually added model IDs (`claude-sonnet-5`, `claude-opus-5`, `claude-haiku-4-5-20251001`) since the connection didn't auto-populate a model list. Verified with a live chat message — works.

Confirmed no Ollama container is running on the droplet — Open WebUI ships with an Ollama connection slot by default but it's a no-op here (nothing listens on `localhost:11434`); all inference goes out to Anthropic's API. Droplet stays on the $12/mo tier since it's doing no local model work.

## Problems hit along the way (and the actual fixes)

- **SSH to the droplet failed with "Host key verification failed"** despite a matching key already in `known_hosts` — caused by OpenSSH's `UpdateHostKeys` behavior trying to prompt for confirmation of additional/rotated host keys, which needs a TTY that wasn't available. Fixed with `-o UpdateHostKeys=no`.
- **Wrong assumed SSH user** — tried `bystrek` (the droplet's hostname, not a login user) and got `Permission denied (publickey)`. The actual login user is `root`.
- **Caddy kept redirecting `https://bystrek.dev/` to itself (308 loop) after the Caddyfile was updated** — Caddy only reads its config file at container startup; swapping the bind-mounted `Caddyfile` on disk doesn't take effect until it's told to reload. Fixed with `docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile`, which picked up the new `reverse_proxy open-webui:8080` target immediately (no container restart, no cert re-issuance needed).
- **Open WebUI took ~1–2 minutes to report healthy on first boot** — normal; first run downloads the `sentence-transformers/all-MiniLM-L6-v2` embedding model (used for RAG) from Hugging Face before the health check passes.

`https://bystrek.dev` (Tailscale-only) now serves a real Open WebUI instance backed by Claude, with a persistent volume for its data. `~/bystrek/docker-compose.yml` and `~/bystrek/Caddyfile` on the droplet were backed up to `.bak` copies before editing. See `whats-next.md` for what's left.
