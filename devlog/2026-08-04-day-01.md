# Day One — bystrek.dev

**Date:** 2026-08-04
**Goal:** Stand up the infrastructure for a personal AI assistant (Open WebUI + Claude) that can manage calendar and notes, starting with iCloud Calendar.

## What we decided

**Concept**: Open WebUI as the chat frontend, connected to Claude, with custom "Tools" (Python) giving Claude the ability to call out to iCloud Calendar via CalDAV. Notes integration deferred — no clean API for iCloud Notes, and the user wants to evaluate a separate notes/reminders app rather than fight AppleScript.

**Hosting**: needed to run 24/7, so moved from "run locally" to a VPS. Ruled out plain public HTTPS exposure early — the assistant will hold a Claude API key and (eventually) an iCloud app-specific password, so we didn't want a login page reachable by the whole internet.

**Access model — Tailscale**: chosen over Cloudflare Tunnel. Both avoid opening inbound ports on the VPS, but Cloudflare Tunnel still publishes a real public hostname gated by an access policy, whereas Tailscale keeps the box off the public internet entirely (private WireGuard mesh, no public DNS resolution of anything sensitive). Mechanism explained in detail: Tailscale is both a small cloud coordination service (login, device registry, key exchange) and a local client on each device; actual traffic flows peer-to-peer over encrypted WireGuard, not through Tailscale's servers.

**VPS provider**: compared Hetzner, DigitalOcean, Vultr, and Linode/Akamai on price and signup friction.
- Hetzner: cheapest, but no social login and a manual KYC review step.
- Vultr: has a Warsaw datacenter (ideal for the user, based in Warsaw) and social login *in theory* — but the user hit a bug where Google/GitHub login didn't actually work.
- Landed on **DigitalOcean**: reliable social login, best documentation/tutorials, region choice narrowed to Frankfurt or Amsterdam (closest EU regions to Warsaw; DO has no Warsaw datacenter).

**Domain**: considered using the user's surname, then flagged a real risk — Certificate Transparency logs permanently and publicly record any hostname a TLS cert is issued for, so `assistant.surname.com` would tie the user's real identity to "runs a self-hosted AI assistant with calendar access," a useful detail for anyone targeting them for phishing. Decided on an invented, non-identifying domain instead. Went through several rounds of invented-word suggestions (4, 5, 6 letters), then leaned into Polish phonetics per the user's heritage (Warsaw-based, Polish surname). Landed on **bystrek.dev** (from *bystry*, Polish for "sharp-witted/quick") registered via Cloudflare.

## What we actually built today

1. **Droplet**: DigitalOcean, $12/mo tier, Docker Marketplace image (Docker + Compose preinstalled), SSH-key auth only (ed25519 key generated for this project).
2. **Smoke test**: ran a throwaway `nginx` container, confirmed reachable over the droplet's public IP — proved the box, Docker, and networking all worked before locking anything down.
3. **Tailscale**: installed on the droplet and on the user's Mac, joined to the same tailnet. Verified the droplet is reachable over its private Tailscale IP.
4. **Locked down the public IP**: added a DigitalOcean Cloud Firewall allowing only inbound SSH; confirmed via `ping`/`curl` that the public IP is now unreachable while the Tailscale IP still works.
5. **Domain pointed at the droplet privately**: added a Cloudflare DNS A record for `bystrek.dev` → the droplet's Tailscale IP, set to "DNS only" (not proxied) so Cloudflare's edge never tries to reach the private address.
6. **Real HTTPS, no public ports needed**: built a custom Caddy image (via `xcaddy`) with the Cloudflare DNS plugin, so Caddy can prove domain ownership and get a trusted Let's Encrypt certificate purely via DNS-01 (a temporary TXT record through the Cloudflare API) — no port 80/443 exposure required at any point.
7. Confirmed working end to end: `https://bystrek.dev` loads a custom test page, over Tailscale only, with a real trusted certificate.

## Problems hit along the way (and the actual fixes)

- **Heredoc paste into SSH session silently failed** → switched to a single-line `printf` to write the test HTML file reliably.
- **Opera showed `ERR_CONNECTION_REFUSED`** → two compounding causes: (a) browser was defaulting to HTTPS on port 443 before we'd set up TLS at all — fixed by testing with an explicit `http://` scheme first; (b) Opera had cached the failure and needed a full quit/reopen, not just an incognito window.
- **`xcaddy` build took ~2.5 minutes** — normal; it's compiling Caddy from source with the Cloudflare plugin bundled in, not pulling a prebuilt image.
- **Caddy ignored our `Caddyfile` entirely** (log: "no automatic HTTPS will be applied") → the `Dockerfile` only builds the Caddy binary, it never copies our config in, and `docker-compose.yml` didn't mount it either. Fixed by adding `./Caddyfile:/etc/caddy/Caddyfile` as a volume mount.
- **DNS-01 challenge failed with `SERVFAIL` on `_acme-challenge.bystrek.dev`** — the trickiest one. Verified Cloudflare's DNS was fine (direct DoH query returned the correct NXDOMAIN+SOA-authority response) and the DigitalOcean firewall's outbound UDP was open, which ruled out the domain and the firewall. Root cause: the container inherited a DNS resolution chain that ran through Tailscale's DNS proxy (visible via the `search tail85a641.ts.net` entry in `resolv.conf`), which was returning `SERVFAIL` for this specific lookup. Fixed by pinning the Caddy container to public resolvers directly (`dns: [1.1.1.1, 8.8.8.8]` in `docker-compose.yml`), bypassing that chain.

## Landing page (2026-08-05)

Replaced the placeholder nginx test page with a real landing page for Bystrek.

**Design**: single-screen, no-scroll layout, asymmetric composition (wordmark anchored lower-left, mono status line bottom-right). Palette is bordeaux/cherry + cream (user's favorite colors) — deep wine bordeaux and cherry as the accent, warm cream as the ground, muted brass gold for hairline details; dark mode flips the relationship (wine becomes the background, cream becomes the ink). Typography: Bodoni Moda (sharp, high-contrast serif) for the "Bystrek" wordmark, Work Sans for the tagline, IBM Plex Mono for the status line. All three fonts embedded as base64 `@font-face` data URIs so the page is a single self-contained HTML file with no external requests. A slowly-rotating wax-seal ring (drawn on canvas) sits in the top-right corner, and a breathing pulse dot marks the status line ("reachable only over Tailscale · bystrek.dev"); both respect `prefers-reduced-motion`.

**Deployed**: backed up the existing placeholder on the droplet to `~/bystrek/index.html.bak`, then `scp`'d the new page over `~/bystrek/index.html`. No container restart needed — `index.html` is bind-mounted into the `web` (nginx) container, and Caddy's existing HTTPS setup picked it up immediately. Verified live at `https://bystrek.dev` over Tailscale.
